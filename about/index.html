How we work

Three habits we stick to

1

Research, then prototype, then product

We first learn how the work is done in a sector. Then we build a small working version and try it. Only then do we turn it into a product.

2

Reuse before building

If a tool you already have, or a small change, fixes the problem, we say so. We build new software only when it is clearly worth it.

3

True claims only

We don't publish numbers or results we can't back up. When we use a figure to explain something, we mark it as an example.

The method

VALUE OS: how a diagnostic runs

VALUE OS is the five-step method we use in advisory work. It keeps every diagnostic grounded in what really happens in the business, not in opinions.

  1. Step 1

    Baseline

    Write down how the work is done today and how long it takes, from your real files and short conversations with the people who do it.

  2. Step 2

    Diagnose

    List the places where time or money seems to leak, and check each one against the records. Some turn out to be real; some don't.

  3. Step 3

    Quantify

    Put a rough number on each real finding, in hours a month or rupees a year, so they can be compared side by side.

  4. Step 4

    Design

    Rank the fixes by value and effort, note what each one needs, and agree what to do first.

  5. Step 5

    Drive

    If the firm wants to go ahead, build the fix and measure it against the baseline from step 1.
